## 2. 記號面板

### 2.1 資料：面板只呈現登記表（`symbols.py`）

面板、搜尋、停用原因、說明條、譜面繪製都讀同一份登記表（D1）。`symbols.py` 已有 `hidden`、`print_only`、`slot`、`on_rest`、`family`、`bar_edge`、`CATEGORY_NAMES`、`GROUP_NAMES`、`search()`；介面還需要**新增**以下欄位，請資料模型建造者先對齊介面（設計者沒有改 src）。另外現行 `search()` 是子字串比對，實測「hua」會找到 `bar.double`（shuang），要改成 §2.4 的音節比對與排序：

| 欄位 | 用途 | 來源 |
|---|---|---|
| `short_tw` / `short_cn` | 格子上的短名，最多 6 個全形字寬 | 預設＝名稱去掉全形括號內的部分（`D.C. al Fine（僅文字）` → `D.C. al Fine`），個別手修 |
| `usage_tw` / `usage_cn` | 說明條一句用法，≤ 30 字，說「什麼時候用、效果是什麼」 | 可用本地模型起草，人工逐條審過（178 條） |
| `pinyin` | 名稱的無聲調拼音音節，空白分隔（`shang hua yin`） | 開發時用 pypinyin 產生並寫進登記表，執行時不依賴套件 |
| `CATEGORY_SHORT` | 分類欄用的 2–3 字短名（段頭仍用 `CATEGORY_NAMES` 全名，如「民樂技法」） | 指法、技法、演奏法、力度、線條、裝飾音、小節線、跳躍、速度、踏板 |
| `in_palette` | 是否出現在面板；`volta.end` 為 False | 新增 |
| 預覽圖 | `assets/symbols/<id>.png`：每個記號掛在音符 5 上，用**真的 LilyPond 2.26** 排出後裁切的黑白圖（2x），深色模式下改用文字色著色 | 打包前由腳本產生並納入版控；不在執行時跑 LilyPond |

### 2.2 結構（由上到下）

1. **搜尋框**（34 高，佔滿寬）：提示文字「搜尋記號：滑、hua、slide」，右側鍵帽 `/`。有字時顯示「N 個結果」與清除 ×。
2. **樂器篩選**（單選膠囊）：**二胡（預設）｜古箏｜琵琶｜笛子｜通用｜更多…**（更多：中阮、葫蘆絲、揚琴、全部）。選某樂器＝「通用 ＋ 該樂器」；「通用」＝只有 common 群組。記住上次選擇。實際數量（symbols.py 實測，不含隱藏與 volta.end）：二胡 120、古箏 107、琵琶 103、笛子 109、通用 98、全部 150。
3. **分類欄＋格子**：左側 64 寬直欄（EOP 使用者熟悉的右側分頁條，但有字），項目依序是：**常用、最近、指法、技法、演奏法、力度、線條、裝飾音、小節線、跳躍、速度、踏板**（`CATEGORY_SHORT`）（對應登記表 cat：fingering、technique、articulation、dynamic、line、ornament、barline、navigation、tempo、pedal）。右側是一條連續捲動的格子，每個分類一段，段頭用全名，如「民樂技法 · 二胡 13」。點分類欄＝捲到那一段；捲動時分類欄跟著標示目前段落。不做「點分類只顯示那一類」的篩選，這樣不用切換也能一路往下看完。
   - **常用**（我的最愛）：最多 9 個，`Alt+1…9` 直接套用（mac 為 `⌥1…9`）。以「圖＋名＋鍵號」小膠囊呈現。格子右鍵「加到常用／移出常用」，在常用段內可拖曳排序。預設：一指、二指、三指、拉弓、推弓、揉弦、上滑音、mf、連線。
   - **最近**：最近用過的 8 個，自動更新。
4. **說明條**（96 高）：顯示滑鼠停住的格子；沒有就顯示鍵盤焦點所在格子；再沒有就顯示上一次套用的記號。內容：左側 86 寬「**印出來長這樣**」預覽圖（§2.1 的真實排版圖）；右側完整名稱（粗）、一句用法、（停用時）黃底原因、底行小字：🔇「試聽不表現，只印出」（只對 `print_only`）、目前會發生的事（「會取代：雙小節線」「再點一次會移除」）、常用鍵號、「加到常用 ☆」。

### 2.3 格子

- 預設尺寸 3 欄 × 72 寬 × 62 高（間距 4）；窄版 2 欄 × 38 高左圖右字。**任何預設尺寸都有字，不做只有圖示的格子。**
- 圖：我們自己畫，與譜面同一套繪製程式（不是另一份圖示），掛在一個淡灰的「5」上，看得出記號在音符的上、下、左或兩音之間。小節類畫在一條淡灰小節線上。
- 名稱：12 px，一行，超出用「…」，完整名稱在提示與說明條。
- 標籤：`只印`（左上角，給反覆跳躍裡僅文字／僅符號的項目）。
- 狀態：

| 狀態 | 樣子 | 說明條 |
|---|---|---|
| 可用 | 白底、細框 | 用法 |
| 滑鼠停住／鍵盤焦點 | 竹青框＋2 px 淡竹青外圈；同時在**譜面上把目標標出來**（要加的音或小節邊界描竹青框） | 用法＋「會加在：第 7 小節第 1 音」 |
| 已加在目前選取上 | 淡竹青底、竹青框、右上 ✓ | 「已加上，再點一次移除」 |
| 部分已加（多選時） | 半個 ✓（右上 ✓ 加小字「2/4」） | 「4 個音中有 2 個已有；點一下全部加上」 |
| 會取代 | 一般樣子 | 「會取代：二指」 |
| 停用 | 透明底、虛線框、圖 38% 不透明、名字保持次要文字色（仍可讀，對比 ≥ 4.5） | **黃底原因＋怎麼做**（見 §2.5） |

### 2.4 搜尋

- 符合範圍：繁體名稱、簡體名稱（不管介面是哪種文字，兩種都比對，「滑」與「滑」、「顿」與「頓」都找得到）、拼音、英文 id 與登記表 keys。
- 拼音以**音節**比對：先把查詢字串切成音節（hua → [hua]；huayin → [hua, yin]），音節完全相同的排在前面，最後一個音節可以只打開頭（`hua` 也會找到 `huan qi`，但排在後面）。不做字串任意子字串比對（否則 `hua` 會找到 `shuang`）。
- 排序：名稱以查詢開頭 ＞ 名稱包含 ＞ 拼音音節完全符合 ＞ 拼音開頭符合 ＞ 英文 id／keys；同分時目前樂器的記號在前，再依登記表順序。
- 搜尋時**不受分類與樂器篩選限制**（找得到任何東西），結果改成**清單**：每列 48 高，圖、完整名稱（符合處用竹青粗字標出）、第二行「技法 · 二胡」＋該列狀態（✓ 已加在這個音／會取代上滑音／⚠ 原因）。
- 被隱藏的待確認記號不列出，但在結果下方說明「另有 3 個『待老師確認』的記號沒有列出：回滑音、墊指滑音、滑揉。**暫時顯示**」。
- 沒有結果：「找不到『xxx』。可以試試：滑音、指法、hua。按 Esc 清除。」
- 「滑」的實際結果（二胡篩選、選一個音）：上滑音、下滑音、大滑音（滑奏線）、連線（圓滑線）；隱藏 3 個。見圖 d。

### 2.5 什麼時候能用：選取 → 目標規則

先決定「目標」，再判斷能不能用。下表就是能不能用的完整規則；停用一律給「原因＋怎麼做」。

| 目前選取 | 點記號（point、pre） | 線條（span） | 小節記號（bar：小節線、房、反覆、跳躍） |
|---|---|---|---|
| 沒有選取 | 停用：「請先在譜上點一個音符」 | 停用：「請先選一段音符（點第一個音，按住 Shift 再點最後一個）」 | 停用：「請先點小節號或小節線」 |
| 1 個音 | 加在這個音 | 延音線、大滑音：從這個音到**下一個音**；其他：停用「需要選取連續兩個以上的音符」 | 加在這個音所在小節（結尾類 → 右邊線；開頭類 → 左邊線） |
| 1 個休止符 | 只有 `on_rest` 的可用；其他停用：「休止符不能加{名稱}」 | 同上 | 同上 |
| 連續多個音 | 加到每個可以加的音；休止符或不能加的略過並提示「已略過 2 個休止符」 | 從第一個到最後一個 | 開頭類 → 第一個小節左邊；結尾類 → 最後一個小節右邊；房 → 涵蓋的所有小節 |
| 不連續多選（Ctrl 加選） | 同上 | 停用：「選取不連續；線條需要一段連續的音」 | 停用：「請只選一段連續的小節」 |
| 整小節（點小節號，可 Shift 多選） | 停用：「目前選的是整個小節；請點小節裡的音符」 | 從小節第一個音到最後一個音 | 同「連續多個音」 |
| 小節線（點兩小節之間的線，±6 px） | 停用：「請點音符」 | 停用 | 結尾類 → 左邊小節的右邊；開頭類 → 右邊小節的左邊；房：停用「房要選小節（點小節號）」 |

其他停用原因（由驗證規則產生，與 tech §1.5 一一對應）：
- 延音線：「下一個音音高不同，不能加延音線（要連貫請用連線）」。
- 三連音：「請選一個沒有附點的音，會拆成三等份」。
- 後倚音：「有後倚音的音只能再加換氣記號」。
- 漸強弱：「漸強弱線不能重疊：第 14–15 小節已有一條」。
- 8va／8vb：「不能跨過反覆或跳躍記號（第 8 小節有反覆止）」。
- D.S.／D.C.：「整首只能有一個跳回記號：第 12 小節已有 D.S.（到那裡移除）」；D.S. 沒有記號 𝄋：「請先在要跳回的地方加 D.S. 記號 𝄋」。
- 第一房：「第一房前面要有反覆：請先加反覆止 :‖」；第二房：「請先加第一房」。
- 導航放在反覆裡：「跳躍記號不能放在反覆或房子裡面」。

**原因文字一律是「現況＋下一步」，不出現 id、欄位名或英文錯誤。**

### 2.6 套用、切換、取代

- **再點一次＝移除**：目標上全部都有這個記號時，點擊移除；否則加上（多選時把缺的補上）。
- **同一槽位只能有一個**（slot：力度、指法、弦序、弓法、滑音、琶音、震音、頓音類、內外弦、裝飾音、換氣、速度文字；小節線樣式 {虛、雙、終止、反覆止、雙向反覆}）：自動取代，並在譜面底部出現提示「已把二指換成一指　**復原 Ctrl+Z**」，4 秒後淡出，滑鼠移上去暫停。
- **線條**：同 family 重疊的舊線被取代，提示「已取代第 14–15 小節原本的漸強」。
- **房子的放法**：使用者照印出來的樣子操作：選第一房的小節 → 點「第一房」；選第二房的小節 → 點「第二房」。`:‖` 畫在第一房結尾（和 PDF 一樣），內部存放位置（tech §1.5：反覆止放在反覆本體結尾）由程式換算，使用者看不到也不用懂。
- **每次套用＝一步復原**。多選套用到 20 個音也是一步。
- **落點回饋**：記號出現在譜面時，先以竹青色、放大 1.2 倍出現，120 ms 縮回原大，再 180 ms 轉回墨色。移除時 120 ms 淡出。系統設定「減少動態」時只有顏色變化。
- **小節記號的範圍**：小節線、房、反覆、跳躍屬於所有聲部（存在 parts[0]），在第二聲部選取時照樣可用，「選取」區標題寫「第 9 小節（所有聲部）」。

### 2.7 連續套用與鍵盤

**連續套用**（JP-Word 的連續貼上）：`Shift`＋點格子、雙擊格子，或按面板上方的「連續套用」開關。開啟後：
- 格子保持竹青框；譜面上方出現一條提示「連續套用：一指 — 點音符加上，再點一次移除。Esc 結束」。
- 游標在譜面上變成帶記號小圖的蓋章游標。點音符＝切換這個記號；線條記號用拖曳選一段；小節記號點小節或小節線。
- 結束：Esc、再點同一格，或點另一格（換成新記號，模式持續）。

**鍵盤流程（不用滑鼠完成）：**

| 按鍵 | 作用 |
|---|---|
| `/` 或 `Ctrl+F`（mac `⌘F`） | 從譜面跳到搜尋框（全選舊字） |
| 打字 | 即時過濾，第一個結果自動標亮 |
| `↓` `↑` | 在結果（或格子）間移動；格子用方向鍵四向移動，`Home`／`End` 到首尾 |
| `Enter` | 套用標亮的那一個，**回到譜面**（保留選取，可以繼續輸入音符） |
| `Ctrl+Enter` | 套用但留在面板（連續加好幾個） |
| `Shift+Enter` | 進入連續套用 |
| `Esc` | 搜尋框有字 → 清空；沒字 → 回到譜面；連續套用中 → 結束 |
| `Alt+1…9` | 套用常用第 1–9 個（譜面有焦點時） |
| `F6` / `Shift+F6` | 在 譜面 → 記號面板 → 選取區 → 曲目列 之間輪流移動焦點（Windows 慣例） |
| 選單鍵／`Shift+F10` | 譜面右鍵選單，第一項「加記號…」（等於 `/`），接著是最近用過的 5 個記號 |

## 3. 譜面呈現

### 3.1 字與尺寸（100% 縮放）

- **簡譜數字**：Nimbus Sans Regular（LilyPond 2.26 內附，PDF 上的數字就是它），啟動時用 `QFontDatabase.addApplicationFont` 從內附 LilyPond 目錄載入；失敗才退回 Arial／Helvetica，並記錄一次。21 px，常規字重（0.3.1 的粗體與 PDF 不一致）。數字只用墨色；選取用底色表示，不改字色。
- 八度點：半徑 1.8，高音點在基線上 20 px，低音點在最下面一條底線下 4 px。減時線：1.3 px，間距 4 px，同一拍內相連。增時線：12 px 長、1.7 px，置於數字中段。附點：數字右側 10 px。
- **力度**：C059 Bold Italic 15 px（LilyPond 內附，接近 PDF 的力度字）。速度與跳躍文字（rit.、D.S.、Fine）：C059 Italic 13 px。技法中文字（內、頓弓）：介面 CJK 字型 11.5 px、字重 500，依「技法字印繁／簡」設定決定字形。
- 小節線 1.1 px；粗線 3.4 px；虛線 4/3。小節號 11 px 次要文字色，放在小節左上角。

### 3.2 記號的位置：逐音由內往外堆，不重疊

- 每個音上方由近到遠依序堆：**（若在連線下方）連線弧 → 指法／弦序 → 演奏法符號（頓音、重音、裝飾音、延長） → 弓法 → 技法文字 → 速度文字**；每層 13 px。只堆這個音真的有的記號，不留空層（避免記號浮在半空，見早期 mockup 的教訓）。
- 下方由近到遠：減時線與低音點 → 震音斜線 → **力度與漸強弱（同一系統內對齊成一條橫線）** → 踏板 → 歌詞。
- 前置（滑音、琶音）畫在數字左側 11–17 px；換氣、停頓畫在右側。
- 房子的括線在該系統最上層，小節號之上；跳躍符號（𝄋、⊕）在小節線上方，文字類（D.S. al Coda、Fine）靠小節右緣、最上層。
- 系統之間的距離依實際內容計算（不是固定行高），同一系統裡的兩聲部間距依上一聲部的下方內容與下一聲部的上方內容決定。
- 這是畫布的近似排版；分頁、換行與精確位置以 LilyPond PDF 為準（列印預覽）。

### 3.3 多聲部

- 一個系統＝所有聲部上下排列，左側大括號，小節線貫通所有聲部（同 PDF）。左側 74 px 留給聲部名稱（12 px）。
- **目前編輯的聲部**：名稱竹青色粗體、該列整條淡竹青底（6% 透明）、紙張最左緣 3 px 竹青直條。其他聲部照常墨色，不變淡（要能對照著讀）。
- 游標、選取、輸入只發生在目前聲部；點另一聲部的任何音＝切換聲部並選那個音。
- 切換：點聲部膠囊、點譜面左側聲部名稱、`Alt+↑`／`Alt+↓`（游標停在同一個時間位置）。
- 新增聲部（曲目列「＋」）：預設名稱「二胡二」，內容是與第一聲部等長的休止符；總拍數必須相等（tech §1.5），不等時該聲部尾端出現斜線底的「缺 2 拍」區塊。

### 3.4 弱起、反覆、小節線、跳躍

- **弱起**：第一小節依實際長度變窄（以拍數比例），小節號位置寫「弱起」，後面從 1 開始編號。曲目列「弱起」下拉只列合法長度（八分、四分、附點四分、二分…，且小於一小節）。最後一小節長度不符時，該小節出現問題標示「有弱起時，最後一小節應為 1¾ 拍或完整 2 拍」，旁邊有「補齊休止符」。
- 反覆起／止：粗細線加兩點（每個聲部各兩點）；曲首的反覆起照樣畫（tech P6）。雙小節線、終止線、虛小節線照 PDF 形狀。
- 房：括線＋「1.」「2.」「結」；最後一房右端開口。只畫在最上面的聲部上方。
- **只印不播的提示**：譜面平常不加標記（不弄亂譜面）。滑鼠停在這類記號上時出現提示「只印出，試聽不會表現」；試聽中播到這類記號時，狀態列的試聽膠囊旁短暫顯示「🔇 rit. 只印」。適用：速度文字、延長記號、裝飾音、滑音、大滑音、僅文字／僅符號的跳躍記號、除了 trem.3 以外的震音。

### 3.5 選取、游標、懸停與試聽位置

| 狀態 | 畫法 |
|---|---|
| 懸停音符 | 22×31 圓角 5 淡灰底（hover） |
| 選取音符 | 同大小、選取底色＋1.5 px 竹青框 |
| 選取小節 | 整個小節（貫穿所有聲部）淡竹青底＋竹青框，小節號變竹青實心小膠囊 |
| 選取小節線 | 小節線改竹青、3 px 淡竹青外暈 |
| 輸入游標（新增模式） | 2 px 竹青直線在插入點，上端小三角；不閃爍 |
| 填寫模式 | 空白小節中下一個空位畫虛線框 |
| 試聽位置 | 2 px 竹青直線貫穿整個系統，正在播的音數字改竹青；自動捲動讓目前系統留在可視區上半 |
| 面板懸停的目標預告 | 要加的音／小節邊界描 1.5 px 竹青虛線框 |

試聽位置需要「MIDI 時間 → 音符」對照：從模型依反覆、房、D.C./D.S. 展開順序算出（和 LilyPond `\unfoldRepeats` 同規則），不從 MIDI 反推。做不到精確對照時只顯示時間，不顯示錯的位置。

### 3.6 問題標示與空狀態

- **節奏不完整**：該小節該聲部下方畫琥珀色虛線＋小膠囊「⚠ 少 1 拍」；小節號也加 ⚠。狀態列「⚠ 1 個問題 ›」點擊依序跳到每個問題。成對記號只剩一半（反覆起缺反覆止、房不連號）：該小節線琥珀色外框＋膠囊「反覆起缺少反覆止」。**有問題仍可存檔；匯出 PDF 前提示問題清單**，可「仍要匯出」或「先去修正」。
- **新的空白樂譜**：一個空白小節，裡面淡色提示字「按數字鍵 1–7 輸入音符，0 是休止符；Q W E R A S 換時值」，輸入第一個音後消失。曲名欄顯示「未命名樂曲」佔位字。
- **空聲部**：休止符，不特別提示。

- 陰影只有一種：譜紙（淺色 `0 1 2 /10%` ＋ `0 4 14 /8%`；深色改 1 px 邊框＋較深陰影）。Qt 實作：在譜面 `paintEvent` 自己畫 3 層半透明矩形，不用 `QGraphicsDropShadowEffect`（大面積時太慢）。

### 4.3 字型與字級

| 用途 | Windows 繁 | Windows 簡 | macOS 繁 | macOS 簡 |
|---|---|---|---|---|
| 介面 | Microsoft JhengHei UI → Microsoft JhengHei → Segoe UI | Microsoft YaHei UI → Microsoft YaHei → Segoe UI | PingFang TC → .AppleSystemUIFont | PingFang SC → .AppleSystemUIFont |
| 簡譜數字 | Nimbus Sans（內附）→ Arial | 同 | Nimbus Sans（內附）→ Helvetica | 同 |
| 力度／斜體文字 | C059 Bold Italic／Italic（內附）→ Times New Roman | 同 | 同 → Times | 同 |

字級（px）：12 說明與標籤（中文最小 12，不用 10–11 的中文字；英數小鍵帽可 11）、13 內文與按鈕、14 檔名與說明條標題、15 曲名欄、21 譜面數字與譜面標題。字重只用 400、500、600。數字用等寬數字（`font-variant-numeric: tabular-nums` 在 Qt 用 `QFont.setFeature("tnum")`，6.7+；不支援時接受）。

**Windows 的 JhengHei UI 字面比 PingFang 寬約 5–8%**：所有固定寬度的元件（分段鈕、分類欄、格子）以 Windows 實測為準，驗收時兩種語言兩個平台都要截圖檢查沒有被切字。

### 4.4 Fusion＋一份由代幣產生的 QSS

- 啟動第一件事：`QApplication.setStyle("Fusion")`，再 `setPalette(palette_from(tokens))`；**不用平台原生樣式**。這直接解決 mac 深色截圖的三個問題：未上樣式的區域吃到系統深色調色盤（黑色空白）、QGroupBox 標題被框線穿過、原生下拉箭頭與 QSS 混用後變形。
- 新增 `theme.py`（建造者）：`TOKENS = {"light": {...}, "dark": {...}}`、`build_palette(t)`、`build_qss(t, fonts)`、`canvas_colors(t)`；QSS 與譜面顏色同源。
- 外觀：「跟隨系統」讀 `QStyleHints.colorScheme()` 並監聽 `colorSchemeChanged`；使用者強制淺／深色時用 `styleHints().setColorScheme()`（Qt 6.8 起）。切換時重套 palette、QSS、重繪譜面，不重開視窗。Windows 標題列深色需實測（Qt 6.8 應會跟隨；不行就用 DwmSetWindowAttribute 20）。
- QSS 規則（全部從代幣產生）：
  - **禁用 QGroupBox**；區塊標題用 QLabel（12 px、600、text2）＋分隔線。
  - 按鈕用屬性區分：`kind="primary|line|ghost|icon"`；分段鈕是一組 QToolButton，用 `position="first|middle|last"` 屬性決定圓角。
  - QComboBox：`::drop-down` 寬 22、無框；`::down-arrow` 用 `chevron-down` SVG，依主題各產生一份著色檔放在快取資料夾（QSS 的 `image:` 只能用檔案路徑）。
  - QSpinBox（速度）：`setButtonSymbols(NoButtons)`，用滾輪與 ↑↓ 調整，避免 Fusion 的小箭頭在深色下難看。
  - QScrollBar：10 px 寬、圓角把手、無箭頭。QToolTip：raised 底、text 字、border 框、8 px 內距。QMenu：raised 底、選中項 accentsoft。
  - 焦點：所有可聚焦控件 `:focus` 用 2 px accent 框（QSS 沒有外暈；搜尋框的 3 px 淡竹青外圈在自繪元件裡才有，QSS 元件只用 2 px 框）。
- 自繪元件（譜面、記號格子、搜尋結果、選取膠囊）一律從 `canvas_colors(t)` 取色，不寫死顏色（0.3.1 的 `#344c59` 等常數要全部換掉）。

## 7. 驗收清單（建造者自查、獨立審查者複驗；全部要截圖或實際操作證據）

尺寸與版面
1. 1380×850 與 1000×630 兩種視窗，繁中與簡中各一張截圖（共 4 張）；任何文字都沒有被切掉或重疊（Windows JhengHei UI 與 mac PingFang 各驗一次）。
2. 1380×850 時譜面可視區 ≥ 1000×600；1000×630 時 ≥ 700×400（量截圖）。
3. 960×600 最小視窗：§1.3 的「不收的東西」全部可見可點。
4. 拖寬到 1920×1080：右側面板 ≤ 360，多出的寬度變成每行更多小節。
5. Windows 150% 與 200% 縮放、mac 2x：圖示清楚無鋸齒，譜面線條沒有糊掉。
6. 音高、時值按鈕 ≥ 26×26；所有可點目標 ≥ 24×24（WCAG 2.2 目標尺寸最低要求）；膠囊的 × 點擊區 20×20 以上且與相鄰目標間距 ≥ 4。

顏色與主題
7. 兩種主題下 §4.1 每一組對比都用程式從實際 palette 讀值計算並附數字，≥ 4.5（文字）／3.0（元件邊框、選取框）。
8. mac 深色模式實機截圖：沒有黑色未上樣式區塊、沒有被框線穿過的標題、下拉箭頭完整（對照 work/macos/macos-ui.png 的三個問題）。
9. 「跟隨系統」時切換系統深淺色，程式在 1 秒內跟著換，不重開、樂譜不變。
10. 原始碼沒有寫死顏色：`rg '#[0-9a-fA-F]{6}' src/` 只出現在 theme 代幣檔。

記號面板
11. 面板顯示的記號數＝登記表中非隱藏的數量（全部 150、二胡 120；以 `symbols.py` 當下資料計算，不寫死），程式測試比對。
12. 二胡篩選下：「滑」「hua」「slide」第一筆都是上滑音，前 4 筆是上滑音、下滑音、大滑音、連線（圓滑線）；「顿」前 3 筆是頓音、頓弓、連頓弓（順序不限）；「dunyin」第一筆是頓音；「hua」不會找到「雙小節線」（shuang）。
13. 搜尋時打字到結果出現 ≤ 50 ms（記錄環境與量測值）。
14. 每個停用的格子與結果，滑鼠停住與鍵盤焦點時都顯示原因；用程式列舉所有面板記號 × §2.5 的 7 種選取情境，原因字串都非空、都是使用者語言（沒有 id、底線、英文錯誤）。
15. 同槽位取代時出現提示且「復原」一步回到原狀；再點一次已加上的記號會移除。
16. 多選 20 個音套用＝一個復原步驟；有休止符時提示略過幾個。
17. 連續套用：開啟後點 5 個音各加上記號，Esc 結束，游標恢復。
18. 說明條預覽圖是 LilyPond 產生的檔案（檔案存在、每個非隱藏記號一張，深色模式下看得清楚）。
19. 小節記號選取規則照 §2.5：點小節線加「反覆起」→ 加在右邊小節左側；點小節號加「終止線」→ 加在該小節右側；第二聲部選取時加小節線，PDF 兩個聲部都有。

譜面
20. 一個音同時有指法、弓法、內弦、頓音、力度：截圖中沒有任何重疊，堆疊順序照 §3.2。

25. `F6` 依序經過 譜面、記號面板、選取區、曲目列。
26. 每個輸入都在 100 ms 內有看得見的回應（按鍵按鈕亮、選取框、落點動畫、提示）；開「減少動態」後回應仍在（只有顏色）。
27. 繁↔簡切換 1 步完成，復原紀錄仍可一路復原到開檔狀態。
28. 第一次開啟到第一次試聽，在不看文件下 ≤ 60 秒（找 1 位沒用過的人計時，記錄結果，不代替）。
29. F1 快捷鍵表可搜尋、可同時寫譜；表內每個快捷鍵實際按下都有效。
30. 所有停用的「按鈕」（不只格子）都有提示說明為什麼不能用（例：「重複小節：請先點小節號選取小節」）。

## 8. 明確不做（與理由）

| 不做 | 理由 |
|---|---|
| Ribbon（Office 式大工具列） | 佔高度，與「譜面最大」衝突；記號用搜尋＋分類更快 |
| 可自由拖放、浮動的 QDockWidget 面板 | 版面跑掉後一般使用者救不回來；只允許拖寬右側面板與 F4 收合 |
| 從面板把記號拖到音符上 | 拖放要精準瞄準，點選＋套用更清楚；連續套用已涵蓋大量放置 |
| 只有圖示的格子、JP-Word 式 1000 個無名字形 | 目標使用者不認得記號外形；每格都有名字，數量依登記表 |
| 會擋住操作的導覽（一步步彈窗） | 使用者想直接寫；改用可忽略的引導列 |
| 主畫面即時 LilyPond 排版 | 每次修改要數秒；主畫面用自繪，PDF 按需產生（0.3.0 已定） |
| 自訂無邊框標題列、毛玻璃、半透明 | Qt Widgets 跨平台表現不一致，且 mac 不支援 vibrancy |
| 改用 Qt Quick／QML | 重寫成本高，本版不需要 |
| 紙張材質圖片、擬物木紋 | 裝飾；在 16 px 圖示與深色模式都會出問題 |
| 記號用彩色區分種類 | 印出來是黑白；顏色只保留給「操作狀態」 |
| 裝飾音、滑音、速度文字在試聽時發聲 | MIDI 無法誠實重現（tech §3.3）；改為明示「只印」 |
| 全部控件 44 px 觸控尺寸 | 桌面滑鼠使用，會吃掉譜面；採 WCAG 2.2 的 24 px 最低值，常用鍵 30 px |
| 迷你地圖、頁面縮圖導覽 | 樂譜通常 1–3 頁，跳到小節與問題列已足夠 |
| 拼音聲母縮寫搜尋（hy → 滑音） | 誤中率高；音節搜尋已足夠，日後再評估 |

## 9. 給建造者：Qt 對應與做不到的地方

| 介面元素 | 建議做法 |
|---|---|
| 記號格子 | 一個自繪 `SymbolGrid`（QAbstractScrollArea），一次畫所有段落；自己處理懸停、焦點、方向鍵、提示與 `QAccessible` 名稱（「上滑音，技法，可用」／「連線，停用：需要選取連續兩個以上的音符」）。不要 150 個 QPushButton。 |
| 搜尋結果 | QListView＋自繪 delegate（48 高），模型用排序後的 id 清單 |
| 分類欄 | QListWidget（無框、自訂 QSS 左側 3 px 指示條） |
| 選取膠囊 | 自繪 FlowLayout 中的小 QWidget，或一個自繪元件；× 必須可用 Tab 到達 |
| 分段鈕 | QButtonGroup＋QToolButton＋`position` 屬性 |
| 提示（取代、略過） | 譜面視窗內的子 QFrame，自己定位在底部置中；`QPropertyAnimation` 控制透明度 |
| 試聽膠囊 | QFrame＋QToolButton＋QLabel（tabular 數字） |
| 落點動畫 | QVariantAnimation 只重繪那個音的矩形 |
| 開始頁 | 譜面欄內的 QStackedWidget 頁 |

**HTML mockup 做得到但 Qt Widgets 要變通的（已據此調整設計，不承諾逐像素一樣）：**
- 焦點外暈（3 px 淡色外圈）：QSS 沒有 box-shadow → QSS 控件只用 2 px 竹青框；自繪元件（搜尋框外圈、格子懸停）才畫外圈。
- 譜紙陰影：自己畫半透明矩形，不用 QGraphicsDropShadowEffect。
- 搜尋符合字的底線：delegate 中用粗體＋竹青色即可，底線可省。
- 下拉箭頭：QSS 需要實體 SVG 檔路徑，依主題各一份。
- 字型度量：mockup 是 mac PingFang；Windows JhengHei UI 較寬，固定寬度以 Windows 實測為準。
- 曲名「無框、懸停才出框」：QLineEdit＋`:hover`／`:focus` 樣式可做到。

**最有風險的五件事：**
1. **試聽位置與「從選取處試聽」**：MIDI 時間 ↔ 音符需要從模型展開反覆／房／D.C./D.S.（與 LilyPond `\unfoldRepeats` 同規則），且 mac MusicPlayer 與 Windows winmm 取時間的精度不同；對不準時要退回「只顯示時間、從頭播放」，不可顯示錯的位置。
2. **停用原因的完整性**：178 個記號 × 各種選取 × 驗證規則，原因必須由與 `Score.validate` 同一套規則產生，否則面板說可以、套用後卻被驗證擋掉（或相反）。建議先寫「可用性矩陣」測試再做畫面。
3. **房子與反覆的換算**：使用者照印出樣子選小節加房，程式要換算成 tech §1.5 的內部存放位置，並在刪除、清空、複製小節時保持成對；這裡最容易出現畫面與 PDF 不一致。
4. **兩平台字型與寬度**：要在啟動時從內附 LilyPond 載入 Nimbus Sans／C059（路徑在 Windows 凍結版、mac .app、開發環境各不同）；JhengHei UI 比 PingFang 寬，固定寬度元件在 Windows 繁／簡都要截圖驗收。
5. **「印出來長這樣」預覽圖與登記表同步**：150＋27 張真實排版圖要由腳本從登記表產生、裁切、加入版控，登記表一改就要重產；另外 178 條用法說明要人工審過繁簡兩版。這兩項是內容工作量，不是程式，容易被低估。
